# AI usage

This project was built with heavy use of an AI coding assistant (**Claude Code**, Anthropic's Claude Opus model),
working in the repository under the student's direction. This file states plainly what it did and what was
decided or done by a person.

## What the assistant did
* Wrote most of the code: the marketplace port and adapters, the three MCP servers, the LangGraph graphs and
  nodes, the RAG pipeline and variants, the eval runners, the FastAPI backend, the React app, the worker, Docker,
  CI and deployment scripts.
* Wrote the tests (unit, contract, integration, Postgres, worker, HTTP-MCP, API, Playwright) and ran them.
* Ran every evaluation. All numbers in the README, the report and `docs/` come from `evals/results/`, and CI
  checks that.
* Drafted the documentation, the ADRs and the R&D report.
* Built the **stand-in starter kit** (`scripts/make_standin_kit.py`), because the official kit had not been
  released. It then found and fixed a flaw in its own gold labels; see `docs/DATA_CARD.md`.

## What a person decided or did
* Product and scope choices: Groq as the open-model provider, which parts to prioritise, the deployment target.
* Accounts and anything public: the GitHub repository, the cloud VM, API keys, the reviewer login (shared only in
  the private Classroom comment).
* **Judge calibration labels.** The brief requires the student to label 30 proposals themselves. The assistant
  deliberately did *not* fill in `evals/judge/labels.csv`; if those labels are missing, Cohen's kappa is reported
  as pending rather than fabricated.

## Safeguards against AI-generated mistakes
* **Every claim in the agent's own output is verified against evidence.** `rag/verify.py` removes unsupported
  claims before a human sees a draft.
* **No number is hand-typed into the docs.** CI (`scripts/ci/check_numbers.py`) fails if a reported number cannot
  be found in `evals/results/`.
* **Negative results are reported as they came out:**
  - the main retrieval hypothesis was rejected
  - the corrective loop (V8) lowered decision F1
  - better retrieval did not raise the simulated reply rate
  - the X2 A/B test was not significant
* **Threats to validity are listed** in `docs/DATA_CARD.md`. They include the circularity of grading decision
  rules on a dataset generated by the same author.
